# Type Recall 전수 감사 체크리스트

에이전트가 서비스 방향성·품질을 점검할 때 이 목록을 따른다.  
코드/콘텐츠를 바꾸기 전에 **현황 보고**를 먼저 한다.

## 0. 목표 재확인

- [ ] 3층 A(어휘)→B(맥락)→C(판단)가 제품 소개·UI·콘텐츠 비율에 반영되는가
- [ ] 학습자 상정(FE→BE→화면설계→아키텍처)과 무관한 정본이 섞여 있지 않은가
- [ ] “멀리서는 단순, 가까이서는 정교” — 희귀 케이스·교과서 이식·기능 비대화 없는가

## 1. UX/UI

- [ ] 3탭(언어/용어/노트)이 유지되는가. Docs 셸(좌·중·우)이 깨지지 않았는가
- [ ] 판단 시나리오·비교 노트를 **발견**할 수 있는가 (첫 화면 편향 점검)
- [ ] 용어↔노트↔시나리오 점프가 동작하는가
- [ ] 대시보드·통계 위젯·추천 피드가 슬며시 들어오지 않았는가
- [ ] 모바일(<1024) 드로어·타이핑·시나리오 선택 가능한가

## 2. 콘텐츠 균형

수치 수집:

```bash
npm run validate:raw
# generate 로그의 terms 트랙 수·시나리오 파일 목록도 확인
```

- [ ] 시나리오(`scenarios[]`)가 architecture 외 주제에도 있는가
- [ ] 용어 중 drill/노트 연결 비율이 극단적으로 낮지 않은가 (목표: 고아 양산 금지)
- [ ] 노트에 `relatedTermIds` 없는 고아 노트가 늘지 않았는가
- [ ] syntax 트랙 중복(JS/ES6/regex 등)을 키우지 않았는가
- [ ] `_inbox`가 정본을 우회하는 덤프장이 되지 않았는가

## 3. 확장성

- [ ] 한 레슨 카드 수 과다(예: 70+)로 전 파트 동시 렌더가 버거운가
- [ ] `App.tsx`에 무관한 기능을 더 욱여넣으려 하지 않는가
- [ ] generated 전량 번들·URL 라우팅 부재를 알고 있으며, 당장 불필요한 대규모 리팩터를 제안하지 않는가

## 4. raw 관리

- [ ] `manifest.yaml` tracks/terms/notes ↔ 실제 파일 일치
- [ ] `npm run validate:raw` 통과
- [ ] id 중복·깨진 `related*Ids` 없음
- [ ] 애매 자료는 `_inbox` + manifest `inbox:`만

## 5. 안전망

- [ ] raw 변경 후 validate + generate
- [ ] 타이핑·시나리오·점프 변경 시 `npm run test:e2e`
- [ ] visual 이미지는 Pages `base`(`/typeRecall/`)에서도 로드되는가

## 보고 형식

```text
## 판정 요약
- 목표 정합: 맞음 | 부분 | 어긋남
- P0 / P1 / P2 (각 1~5개, 경로·수치 근거)

## 지금 하지 말 것
- (방향 이탈 제안이 나왔다면 여기서 거부)

## 다음 한 수 (콘텐츠 골격 우선)
- (시나리오 1장 또는 비교 노트 1장 또는 링크 보강 — UI는 스키마 막힐 때만)
```
