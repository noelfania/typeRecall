# Language 예문 파트 분할 규칙

`assets/typingSource/Language*` 아래 예문은 화면에서 짧은 파트 단위로 나뉘어 표시된다.
이 문서는 실제 생성 로직 기준으로, 어떤 기준으로 파트가 나뉘는지 정리한 것이다.

## 목적
- 한 파트를 짧게 유지해서 빠르게 타이핑 연습할 수 있게 한다.
- 주석은 화면에 보여 이해를 돕고, 실제 타이핑 대상에서는 제외한다.
- 예문 작성 방식과 앱의 실제 분할 결과가 최대한 같도록 맞춘다.

## 큰 원칙
- 코드 파일과 마크다운 파일은 파트 분할 방식이 다르다.
- 파트 제목은 사람이 읽는 구분용이다.
- 같은 파일 안에서 제목이 반복되더라도 실제 코드 내용이 같으면 중복 파트로 만들지 않는다.
- 제목을 하나도 잡지 못하면 파일 전체를 하나의 파트로 처리한다.

## 코드 파일 분할 기준

대상:
- `.js`
- `.ts`
- `.go`
- `.py`
- `.sh`
- `.java`
- `.rs`
- `.sql`
- `.html`

코드 파일은 **제목용 주석**을 만나면 새 파트가 시작된다.

제목으로 인식하는 주석 형식:
- `/*** 변수 스코프[variable scope] ***/`
- `// 배열[array]`
- `# 조건문[condition]`
- `-- 집계[aggregate]`

### 코드 파일 작성 규칙
- 새 파트를 시작하고 싶으면 제목용 주석을 한 줄로 분명하게 쓴다.
- 제목용 주석은 가능하면 `한글[영어]` 형식으로 쓴다.
- 제목용 주석 아래에는 그 파트에서 연습할 실제 코드만 둔다.
- 결과 설명 주석은 유지해도 된다. 화면에는 보이지만 타이핑 대상에서는 제외된다.
- 한 파트가 너무 길어지면 제목용 주석을 한 번 더 넣어 쪼갠다.

### 제목으로 보기 어려운 주석은 파트 시작점으로 쓰지 않는다
- `// 결과: 123`
- `# 결과: ok`
- `// 1 2 3`
- 코드처럼 보이는 주석
- 기호만 많은 구분선

즉, `결과`, 숫자 출력, 코드 조각처럼 보이는 줄은 제목이 아니라 설명 주석으로 취급한다.

## 코드 파일에서 화면 표시와 타이핑 판정
- 화면에는 제목 주석, 설명 주석, 결과 주석이 그대로 보인다.
- 실제 타이핑 판정은 주석을 뺀 코드 문자만 기준으로 한다.
- 공백과 줄바꿈은 기존 로직대로 무시한다.

예:

### JavaScript

```js
/*** 변수 스코프[variable scope] ***/
var userName = 'kim';   // 사용자 이름[user name]
// 결과: kim
```

이 경우 화면에는 3줄이 보이지만, 타이핑 대상은 `var userName = 'kim';` 만 잡힌다.

### TypeScript

```ts
// 기본 타입[basic type]
let userName: string = 'kim';
// 결과: kim
```

### Python

```py
# 변수[variable]
user_name = "kim"
# 결과: kim
```

### Bash / Shell

```sh
# 현재 작업 디렉터리[current working directory]
pwd
# 결과: /home/user/project
```

### Go

```go
// 변수 선언[variable declaration]
var userName string = "kim"
// 결과: kim
```

### Java

```java
// 문자열[string]
String userName = "kim";
// 결과: KIM
```

### Rust

```rs
// 변수[variable]
let user_name = "kim";
// 결과: kim
```

### SQL

```sql
-- 조건 조회[conditional query]
SELECT name
FROM users;
-- 결과: name 목록
```

### CSS / HTML

```html
/* 카드 강조[card highlight] */
<article class="card-item is-active">
  <h2 class="title-text">카드 1</h2>
</article>
```

`<!-- ... -->` 는 현재 로직에서 파트 시작 주석으로 직접 잡지 않고, `/* ... */` 형태가 실제 제목용 주석 규칙과 더 가깝다.

### RegEx for JavaScript

```js
// 플래그[flag]
const regexValue = /hello/gi;
// 결과: 대소문자 무시 + 전체 검색
```

위 예시들은 모두 화면에는 주석까지 보이지만, 실제 타이핑 대상은 주석을 뺀 코드 본문만 잡힌다.

## 빈 줄 처리
- 빈 줄은 파트 안의 줄 간격으로 유지한다.
- 연속 빈 줄은 정리될 수 있다.
- 파트 맨 앞과 맨 뒤의 빈 줄은 제거한다.

## 마크다운 파일 분할 기준

대상:
- 현재 `Language-git/*.md`

마크다운은 코드 파일처럼 주석 기준으로 쪼개지 않는다.

분할 기준:
- `##` 제목은 큰 섹션 경계로 본다.
- 그 아래에서는 **빈 줄 기준**으로 하나의 카드형 묶음을 한 파트로 본다.

예:

```md
## 기본 흐름

현재 상태를 확인한다.
깃 상태 확인[git status]
예: 작업 전에 `git status`부터 본다.

변경 파일 차이를 확인한다.
차이 확인[git diff]
예: 커밋 전에 `git diff`로 실제 수정 내용을 검토한다.
```

위 예시는 `git status` 묶음이 한 파트, `git diff` 묶음이 다음 파트가 된다.

### 마크다운 작성 규칙
- `##` 로 큰 묶음을 나눈다.
- 한 파트는 가능한 `설명 -> 용어 -> 예문`처럼 짧게 유지한다.
- 빈 줄 하나를 기준으로 다음 파트로 넘어가도록 작성한다.

## 권장 작성 예시

좋은 예:

```js
/*** 배열 구조분해[array destructuring] ***/
var [firstValue, secondValue] = [10, 20];
var [headValue, ...restValues] = [1, 2, 3];
// 결과: firstValue=10, secondValue=20
```

좋지 않은 예:

```js
// 결과: 10
// userName = 'kim'
// ----------------
```

위처럼 결과만 있거나 코드처럼 보이는 주석은 파트 제목으로 쓰기 어렵다.

## fallback 규칙
- 제목용 주석이나 마크다운 카드 경계를 하나도 찾지 못하면 파일 전체를 한 파트로 처리한다.
- 따라서 최소 한 번은 의도적으로 파트 경계를 넣는 것이 좋다.
