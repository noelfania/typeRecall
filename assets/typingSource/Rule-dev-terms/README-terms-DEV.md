# 개발 실무 어휘집

개발 현장에서 자주 쓰이는 실무 영어를 설명형 문제 카드처럼 정리한다.

형식:
- 위 줄: 설명
- 아래 줄: 실제로 많이 쓰는 명칭
- 그 아래 줄: 짧은 예문
- 한글 표기는 뜻을 이해하기 위한 보조용이고, 답은 영어 표현을 익히는 데 집중한다.

## 프로젝트 시작 / 구조

프로젝트의 기본 뼈대나 초기 코드 구조를 자동으로 만들어 주는 작업.
스캐폴딩[Scaffolding / Scaffold]
예: 새 관리자 페이지는 CLI로 scaffold부터 해두자.

프로젝트를 시작할 때 반복해서 쓰는 기본 템플릿 코드.
보일러플레이트[Boilerplate]
예: 인증 로직은 팀 boilerplate를 가져와서 시작했다.

설계 단계에서 전체 구조나 구성 방향을 잡아 둔 청사진.
블루프린트[Blueprint]
예: 구현 전에 페이지 흐름 blueprint를 먼저 그렸다.

실제 콘텐츠가 오기 전에 자리만 먼저 보여주는 뼈대 화면.
스켈레톤 화면[Skeleton / Skeleton Screen]
예: API 응답을 기다리는 동안 skeleton screen을 보여주자.

실제 동작 대신 임시로 넣는 간단한 구현물이나 반환값.
스텁[Stub]
예: 백엔드가 아직 없어서 지금은 stub만 붙여뒀다.

테스트나 개발 중에 진짜 객체 대신 흉내 내는 가짜 객체나 데이터.
목[Mock]
예: 외부 결제 모듈은 mock으로 대체해서 테스트했다.

## 배포 / 환경 / 인프라

한 환경의 프로그램을 다른 환경으로 옮겨 동작하게 만드는 작업.
포팅[Porting / Port]
예: 이 라이브러리는 ARM 환경으로 porting이 필요하다.

개발한 결과물을 실제 서버나 사용자 환경에 올리는 과정.
배포[Deployment / Deploy]
예: 오늘 저녁에 운영 서버로 deploy할 예정이다.

애플리케이션을 컨테이너 기반으로 실행 가능하게 포장하는 작업.
컨테이너화[Containerize / Containerization]
예: 배포 단순화를 위해 앱을 먼저 containerize했다.

서버, 네트워크, 클라우드 자원을 자동으로 준비하고 설정하는 작업.
프로비저닝[Provisioning]
예: Terraform으로 staging 서버 provisioning을 자동화했다.

코드 통합과 배포를 자동화하는 파이프라인 개념.
지속적 통합·배포[CI/CD]
예: 이 저장소는 CI/CD가 붙어 있어서 머지 후 자동 배포된다.

서비스가 늘어나는 트래픽을 감당하도록 확장하는 작업.
스케일링[Scaling / Scale Out / Scale Up]
예: 트래픽이 늘면 우선 scale out부터 검토하자.

요청을 여러 서버로 분산시키는 구성 요소.
로드 밸런서[Load Balancer]
예: 앞단에 load balancer를 두고 요청을 분산했다.

## 코드 구조 / 설계

기능은 유지한 채 코드 구조만 더 좋게 정리하는 작업.
리팩터링[Refactor / Refactoring]
예: 이번 PR은 기능 추가보다 refactoring 비중이 더 크다.

복잡한 내부를 숨기고 필요한 개념만 드러내는 설계 방식.
추상화[Abstraction / Abstract]
예: 공통 API 호출부를 abstraction해서 중복을 줄였다.

데이터와 동작을 하나로 묶고 외부 접근을 제한하는 설계 방식.
캡슐화[Encapsulation / Encapsulate]
예: 상태 변경 로직은 클래스 내부로 encapsulate했다.

모듈 사이의 의존성을 줄여 서로 덜 얽히게 만드는 설계 방향.
디커플링[Decouple / Loose Coupling]
예: UI와 비즈니스 로직을 decouple하는 게 이번 작업의 핵심이다.

필요한 의존 객체를 내부에서 직접 만들지 않고 외부에서 넣어주는 방식.
의존성 주입[Dependency Injection / DI]
예: 테스트 편의를 위해 서비스 인스턴스는 DI로 주입한다.

다른 함수나 객체를 감싸서 사용성을 바꾸거나 기능을 추가하는 래퍼.
래퍼[Wrapper]
예: fetch wrapper를 만들어 공통 에러 처리를 넣었다.

서로 다른 인터페이스를 이어 붙여 호환되게 만드는 중간 계층.
어댑터[Adapter]
예: 레거시 응답 형식은 adapter로 한 번 변환해서 쓴다.

서로 다른 계층이나 구현을 느슨하게 연결하는 구조 패턴.
브리지[Bridge]
예: 렌더러와 컨트롤러를 bridge 패턴처럼 분리했다.

## 빌드 / 런타임 / 성능

소스 코드를 다른 언어나 실행 가능한 형태로 변환하는 과정.
컴파일[Compile / Compilation]
예: 배포 전에 타입스크립트 compile 단계가 먼저 돈다.

한 언어를 비슷한 다른 언어 수준으로 변환하는 과정.
트랜스파일[Transpile / Transpilation]
예: 최신 문법은 Babel이 구형 브라우저용으로 transpile한다.

여러 파일을 묶어 배포 단위로 만드는 작업.
번들링[Bundle / Bundling]
예: 초기 로딩 속도를 위해 bundling 결과물을 쪼개자.

코드 용량을 줄이기 위해 공백과 이름 등을 압축하는 작업.
압축[Minify / Minification]
예: 운영 빌드에서는 minification이 자동 적용된다.

코드 수정 사항이 즉시 반영되도록 다시 불러오는 개발 기능.
핫 리로드[Hot Reload / HMR]
예: 스타일 수정은 HMR 덕분에 바로 확인할 수 있다.

성능을 수치로 측정하고 비교하는 작업.
벤치마크[Benchmark / Benchmarking]
예: 캐시 적용 전후를 benchmark로 비교해보자.

짧은 시간에 너무 많이 호출되는 이벤트를 일정 간격으로 제한하는 기법.
스로틀링[Throttling / Throttle]
예: 스크롤 이벤트는 throttle을 걸어야 부담이 적다.

연속 호출이 멈춘 뒤 마지막 한 번만 실행하게 만드는 기법.
디바운스[Debounce / Debouncing]
예: 검색 입력창은 debounce를 넣는 편이 일반적이다.

병목 지점을 찾기 위해 실행 시간과 자원 사용을 분석하는 작업.
프로파일링[Profiling / Profile]
예: 느린 원인을 찾으려고 먼저 profiling부터 했다.

## 테스트 / 품질

가장 작은 단위의 기능을 독립적으로 검증하는 테스트.
단위 테스트[Unit Test]
예: 유틸 함수는 unit test로 빠르게 검증할 수 있다.

여러 모듈이 함께 동작하는 흐름을 검증하는 테스트.
통합 테스트[Integration Test]
예: 로그인 플로우는 integration test가 더 적합하다.

수정 후에 기존 기능이 깨지는 문제나 그 현상 자체.
회귀 오류[Regression]
예: 이번 수정 때문에 검색 기능에 regression이 생겼다.

시스템이 최소한 실행 가능한지만 빠르게 확인하는 테스트.
스모크 테스트[Smoke Test]
예: 배포 직후 smoke test만이라도 꼭 돌리자.

상식적인 수준에서 큰 이상이 없는지 빠르게 점검하는 확인 작업.
새니티 체크[Sanity Check]
예: 머지 전에 라우팅만 sanity check 해도 사고를 줄일 수 있다.

테스트가 환경이나 타이밍에 따라 들쭉날쭉하게 실패하는 상태.
플래키 테스트[Flaky Test]
예: 그 테스트는 flaky test라서 다시 돌리면 통과하기도 한다.

## 협업 / 커뮤니케이션

아직 끝나지 않고 진행 중인 작업 상태.
진행 중 작업[WIP]
예: 이 브랜치는 아직 WIP라서 리뷰 요청 전이다.

예상 완료 시점이나 예상 소요 시간을 묻는 표현.
예상 완료 시간[ETA]
예: 이 이슈 ETA를 오늘 안으로 공유해줄 수 있을까?

참고만 해 달라는 의미로 공유할 때 붙이는 말.
참고[FYI]
예: FYI, 운영 배포 시간이 내일 오전으로 바뀌었다.

개인 의견임을 전제로 의견을 말할 때 붙이는 표현.
개인 의견[IMO]
예: IMO, 이 함수는 지금 분리하는 편이 더 깔끔하다.

긴 내용을 아주 짧게 요약해서 보여줄 때 붙이는 표시.
요약[TL;DR]
예: TL;DR, 원인은 캐시 키 충돌이고 수정은 이미 끝났다.

작업이나 문서, 책임을 다른 사람이나 다음 단계로 넘기는 과정.
핸드오프[Handoff]
예: 디자인 handoff가 끝나야 개발 일정도 확정된다.

서로 생각이나 방향을 맞추기 위해 짧게 회의하거나 조율하는 것.
싱크업[Sync Up / Align]
예: 이건 먼저 PM이랑 sync up 한 뒤에 진행하자.

## 개발 문화 / 실무 맥락

오래되어 유지보수가 어렵거나 구조가 낡은 기존 코드나 시스템.
레거시[Legacy]
예: 이 모듈은 legacy 코드라 건드릴 때 주의가 필요하다.

아무것도 없는 상태에서 새로 시작하는 프로젝트.
그린필드[Greenfield]
예: 이번 서비스는 완전한 greenfield 프로젝트에 가깝다.

이미 있는 시스템을 기반으로 개선하거나 확장하는 프로젝트.
브라운필드[Brownfield]
예: 기존 ERP 위에 얹는 작업이라 brownfield 성격이 강하다.

지금은 빠르게 만들었지만 나중에 비용으로 돌아올 구조적 문제.
기술 부채[Tech Debt / Technical Debt]
예: 급하게 넣은 예외 처리 때문에 tech debt가 꽤 쌓였다.

짧은 시간 안에 기술 가능성을 검증하기 위해 만드는 실험용 작업.
스파이크[Spike]
예: 본개발 전에 하루짜리 spike로 라이브러리를 검토했다.

아이디어 가능성만 빠르게 확인하는 작은 검증용 결과물.
개념 검증[POC / Proof of Concept]
예: 고객 설득용으로 간단한 POC를 먼저 만들었다.

자사 제품을 내부 팀이 직접 사용하면서 문제를 발견하고 개선하는 문화.
도그푸딩[Dogfooding]
예: 정식 출시 전에 내부 팀이 dogfooding부터 시작했다.
