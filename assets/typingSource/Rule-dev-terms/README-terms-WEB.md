# 웹 실무 어휘집

웹페이지를 만들 때 자주 보게 되는 페이지/섹션/컴포넌트 명칭을 정리한다.

형식:
- 위 줄: 설명
- 아래 줄: 실제로 많이 쓰는 명칭
- 그 아래 줄: 짧은 예문

## 페이지 / 섹션 명칭

웹페이지를 구성하는 여러 구역을 통틀어 부르는 일반 명칭.
페이지 섹션[Page Sections]
예: 이 랜딩 페이지는 5개의 페이지 섹션[Page Sections]으로 나뉜다.

페이지 최상단에 크게 배치되는 대표 소개 영역.
히어로 섹션[Hero Sections]
예: 첫 화면은 히어로 섹션[Hero Sections]에서 메시지를 강하게 보여줘야 한다.

제품이나 서비스의 핵심 기능[feature]을 나열하는 섹션.
기능 섹션[Feature Sections]
예: 제품의 장점은 기능 섹션[Feature Sections]에서 카드 형태로 정리한다.

사용자에게 가입, 구매, 다운로드 같은 행동[action]을 유도하는 섹션.
행동 유도 섹션[CTA Sections]
예: 가격표 아래에 행동 유도 섹션[CTA Sections]을 한 번 더 넣자.

카드 크기를 다르게 섞어 배치하는 격자형 레이아웃.
벤토 그리드[Bento Grids]
예: 대시보드 소개는 벤토 그리드[Bento Grids]가 잘 어울린다.

요금제나 플랜을 비교해서 보여주는 섹션.
가격 섹션[Pricing Sections]
예: SaaS 사이트에서는 가격 섹션[Pricing Sections]이 전환율에 큰 영향을 준다.

페이지 상단에 로고, 메뉴, 버튼 등이 들어가는 머리 영역.
헤더 섹션[Header Sections]
예: 헤더 섹션[Header Sections]에는 로고와 네비게이션을 넣는다.

이메일 구독을 유도하는 뉴스레터 신청 영역.
뉴스레터 섹션[Newsletter Sections]
예: 푸터 위에 뉴스레터 섹션[Newsletter Sections]을 배치해 보자.

숫자 지표로 성과나 규모를 강조하는 섹션.
통계 섹션[Stats]
예: 사용자 수와 전환율은 통계 섹션[Stats]에서 강조한다.

사용자 후기나 고객 리뷰를 보여주는 신뢰 확보 섹션.
후기 섹션[Testimonials]
예: B2B 서비스는 후기 섹션[Testimonials]이 신뢰 형성에 중요하다.

최신 글이나 추천 글 목록을 보여주는 블로그 영역.
블로그 섹션[Blog Sections]
예: 메인 하단에 블로그 섹션[Blog Sections]을 두면 SEO에 도움 된다.

문의 폼, 이메일, 전화번호 같은 연락 수단을 모아둔 섹션.
문의 섹션[Contact Sections]
예: 마지막 구역은 문의 섹션[Contact Sections]으로 마무리하자.

팀원 소개를 위한 구성원 안내 섹션.
팀 섹션[Team Sections]
예: 회사 소개 페이지에는 팀 섹션[Team Sections]이 자주 들어간다.

설명문, 가이드, 문서성 텍스트를 담는 일반 콘텐츠 영역.
콘텐츠 섹션[Content Sections]
예: 긴 설명은 콘텐츠 섹션[Content Sections]으로 따로 빼는 편이 좋다.

고객사, 파트너사, 협업사 로고를 모아 보여주는 영역.
로고 클라우드[Logo Clouds]
예: 협업사를 보여줄 때는 로고 클라우드[Logo Clouds]를 많이 쓴다.

자주 묻는 질문과 답변을 모아 둔 섹션.
자주 묻는 질문 섹션[FAQs]
예: 문의가 많은 서비스라면 자주 묻는 질문 섹션[FAQs]이 꼭 필요하다.

페이지 맨 아래에 회사 정보, 링크, 저작권 등을 넣는 하단 영역.
푸터[Footers]
예: 푸터[Footers]에는 개인정보처리방침 링크를 넣어야 한다.

## 컴포넌트 / UI 명칭

버튼, 카드, 입력창처럼 페이지를 구성하는 작은 단위 요소.
요소[Elements]
예: 버튼과 입력창은 가장 기본적인 요소[Elements]다.

상단 네비게이션 컴포넌트 자체를 가리키는 이름.
헤더[Headers]
예: 모바일에서는 헤더[Headers]를 더 단순하게 만드는 편이다.

호버나 클릭 시 옆이나 아래로 펼쳐지는 확장 메뉴.
플라이아웃 메뉴[Flyout Menus]
예: 카테고리 목록은 플라이아웃 메뉴[Flyout Menus]로 처리할 수 있다.

공지, 할인, 이벤트 같은 메시지를 띠 형태로 보여주는 UI.
배너[Banners]
예: 이벤트 안내는 상단 배너[Banners] 한 줄로 처리하자.

사용자 의견을 받기 위한 별점, 설문, 의견 입력 UI.
피드백[Feedback]
예: 결제 완료 후 피드백[Feedback] 팝업을 띄울 수 있다.

## 전체 페이지 명칭

페이지를 찾지 못했을 때 보여주는 오류 안내 페이지.
404 페이지[404 Pages]
예: 잘 만든 404 페이지[404 Pages]는 이탈을 줄이는 데 도움이 된다.

완성된 페이지 템플릿이나 샘플 화면을 모아 둔 카테고리.
페이지 예시[Page Examples]
예: 디자인 방향을 잡을 때 페이지 예시[Page Examples]를 먼저 본다.

제품 소개와 전환[conversion] 유도에 집중한 단일 목적 페이지.
랜딩 페이지[Landing Pages]
예: 광고 유입은 보통 전용 랜딩 페이지[Landing Pages]로 받는다.

가격 정책과 플랜 비교를 중심으로 구성한 전용 페이지.
가격 페이지[Pricing Pages]
예: 가격 정책이 복잡하면 가격 페이지[Pricing Pages]를 따로 만드는 편이 낫다.

회사, 팀, 미션, 연혁을 소개하는 페이지.
소개 페이지[About Pages]
예: 회사 철학은 소개 페이지[About Pages]에서 자연스럽게 풀어낸다.
