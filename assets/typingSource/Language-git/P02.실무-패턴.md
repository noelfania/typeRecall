# Git 타이핑 연습장 2

## 실무 커밋 패턴

새 기능 추가를 나타내는 커밋 유형.
기능 추가[feat]
예: `feat(auth): add social login`

버그 수정을 나타내는 커밋 유형.
버그 수정[fix]
예: `fix(api): handle empty response`

문서 변경을 나타내는 커밋 유형.
문서 수정[docs]
예: `docs: update setup guide`

동작 변화 없는 구조 개선을 나타내는 커밋 유형.
리팩터링[refactor]
예: `refactor(ui): simplify modal props`

설정, 의존성, 빌드 같은 잡무성 변경을 나타내는 커밋 유형.
잡무[chore]
예: `chore: update eslint config`

## 자주 쓰는 브랜치 패턴

기능 개발용 브랜치 이름.
기능 브랜치[feature branch]
예: `feature/profile-page`

긴급 수정용 브랜치 이름.
핫픽스 브랜치[hotfix branch]
예: `hotfix/login-error`

버그 수정용 브랜치 이름.
버그픽스 브랜치[bugfix branch]
예: `bugfix/cart-total`

## 협업 패턴

원격 저장소 브랜치 목록까지 포함해 최신 상태를 가져온다.
페치[git fetch]
예: 리뷰 전에 `git fetch origin`으로 원격 이력을 먼저 가져온다.

현재 브랜치가 원격과 얼마나 차이 나는지 본다.
로그 비교[git log --oneline --graph]
예: 머지 전에 `git log --oneline --graph --decorate`를 자주 본다.

어떤 파일이 언제 바뀌었는지 추적한다.
이력 추적[git blame]
예: `git blame src/app.ts`로 마지막 수정자를 확인한다.

이전 커밋의 상세 내용을 본다.
커밋 보기[git show]
예: `git show HEAD~1`로 바로 전 커밋 내용을 볼 수 있다.

스테이징하지 않고 임시 저장한다.
스태시[git stash]
예: 급하게 브랜치 바꿔야 할 때 `git stash`로 잠깐 치운다.

임시 저장한 변경을 다시 꺼낸다.
스태시 복원[git stash pop]
예: 돌아와서 `git stash pop`으로 이어서 작업한다.
