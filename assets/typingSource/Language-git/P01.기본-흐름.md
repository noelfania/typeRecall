# Git 타이핑 연습장

## 기본 흐름

현재 상태를 확인한다.
깃 상태 확인[git status]
예: 작업 전에 `git status`부터 본다.

변경 파일 차이를 확인한다.
차이 확인[git diff]
예: 커밋 전에 `git diff`로 실제 수정 내용을 검토한다.

변경 파일을 스테이징 영역에 올린다.
스테이징[git add]
예: `git add src/app.ts`처럼 필요한 파일만 올린다.

스테이징된 변경을 커밋으로 저장한다.
커밋[git commit]
예: `git commit -m "fix: handle null user response"`처럼 의도를 남긴다.

원격 저장소에 변경을 보낸다.
푸시[git push]
예: 작업이 끝나면 `git push origin feature/login`을 실행한다.

원격 변경을 가져와 현재 브랜치에 반영한다.
풀[git pull]
예: 작업 시작 전에 `git pull origin main`으로 최신 상태를 맞춘다.

## 브랜치

새 작업 브랜치를 만든다.
브랜치 생성[git branch]
예: `git branch feature/profile-page`로 브랜치를 만든다.

다른 브랜치로 이동한다.
체크아웃[git checkout]
예: `git checkout main`으로 메인 브랜치로 돌아간다.

브랜치 생성과 이동을 한 번에 한다.
스위치 생성[git checkout -b]
예: `git checkout -b feature/cart`로 새 브랜치에서 바로 작업 시작한다.

최신 방식으로 브랜치를 전환한다.
스위치[git switch]
예: `git switch main`은 브랜치 전환에만 집중된 명령이다.

## 병합 / 정리

다른 브랜치의 이력을 현재 브랜치에 합친다.
머지[git merge]
예: `git merge feature/cart`로 기능 브랜치를 합친다.

커밋을 다시 쌓아 이력을 깔끔하게 정리한다.
리베이스[git rebase]
예: `git rebase main`으로 최신 메인 위에 커밋을 다시 올린다.

충돌 난 파일을 직접 수정한 뒤 병합을 마무리한다.
충돌 해결[merge conflict resolution]
예: 충돌 마커를 지운 뒤 다시 `git add` 한다.

## 복구 / 이동

특정 커밋으로 작업 트리를 되돌린다.
리셋[git reset]
예: `git reset --soft HEAD~1`은 커밋만 취소하고 변경은 남긴다.

기존 커밋을 취소하는 새 커밋을 만든다.
리버트[git revert]
예: 협업 중이면 `git revert <commit>`가 더 안전한 경우가 많다.

특정 커밋 하나만 현재 브랜치에 가져온다.
체리픽[git cherry-pick]
예: 긴급 수정 커밋만 `git cherry-pick <hash>`로 가져올 수 있다.

## 실무 패턴

작업 시작 패턴.
작업 시작 흐름[status → pull → switch]
예: `git status` → `git pull` → `git switch -c feature/x`

작업 저장 패턴.
작업 저장 흐름[diff → add → commit]
예: `git diff` → `git add .` → `git commit -m "..."`

배포 전 반영 패턴.
반영 흐름[switch → pull → merge]
예: `git switch main` → `git pull` → `git merge feature/x`
